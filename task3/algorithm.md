# 跨课题耦合检测算法：伪代码（简洁逐步式）

> 对应 3.3 评分点"给出耦合检测算法的伪代码或流程图（含实体对齐策略、关系推理规则、冲突判定逻辑）"。
> 原理：系统拿到陌生文档，先抽取事实，再对每个跨文档实体自动比对时间轴与技术，主动发现耦合。
> 流程图见 `figures/algorithm_flow.png`。

```
算法：跨课题耦合检测
输入：D = {5 份课题文档}        // 论文手稿、技术专利草稿、实验报告、项目申请书、结题报告
      G = 预埋耦合基准           // 7 处（题目要求 ≥ 6 处）
输出：耦合集合 C                // 每条含 类型/组对/实体/严重度/证据/建议
      P, R, F1                 // 精确率、召回率、F1

Step 1 文档解析
  for d in D:
    S[d] ← LLM解析(d)           // 得 实体(含别名)、事件(带时间)、技术要点、断言

Step 2 实体对齐
  for 每个实体 e:
    e' ← 归一同名(e)            // 别名/全称/缩写归一，如 4块V100 ≡ 老旧V100节点
    记  docs[e'], events[e'], groups[e']   // 该实体涉及哪些文档、事件时间轴、课题组

Step 3 自动发现耦合（大模型自主比较，不预设问题清单）
  // 先汇总：把 5 份文档的实体、事件、技术要点合并为"跨文档事实表"
  F ← {实体: {时间线事件, 涉及文档, 课题组, 技术描述}}

  3.1 实体对齐
      模型比较各文档中不同表述，判断是否指向同一实体并合并
      // 例：模型识别出 4块V100 与 老旧V100节点 是同一资源

  3.2 时序自洽性分析
      对每个共享实体，模型展开其完整时间线，自主判断是否存在不合理关联
      // 例：模型发现"某资源已退役/删除，却有文档在其后仍使用/计划使用"
      //     或 "专利申请早于论文首创声明"、 "资源被多方声称"
      发现异常 → 判为冲突（负耦合）

  3.3 技术关联分析
      对每组课题组，模型比较双方技术要点，自主判断是重叠还是互补
      // 例：模型发现"专利权利覆盖梯度稀疏，与申请书研发方向重叠"→ 重复投入（负）
      //     或 "一方明确采纳对方 APS 作 baseline / 迁移复用" → 协同（正）
      判重叠 → 负耦合；判可复用 → 正耦合

  // 模型对每处发现输出结构化结论：类型 / 组对 / 实体 / 严重度 / 证据句 / 建议

Step 4 冲突判定与规范化
  for c in C:
    补 c.严重度(高/中/低)、c.证据句、c.建议
  去重：按 (类型, 组对, 类别) 合并

Step 5 准确率评估
  for c in C:
    与 G 按 (类型, 组对, 实体) 匹配 → 记 TP 或 FP
  FN ← G 中未命中项
  P = TP/(TP+FP)；R = TP/(TP+FN)；F1 = 2PR/(P+R)
  返回 C, P, R, F1
```

## 与 LLM 实现的对应

| 伪代码步骤 | 实现位置 |
|---|---|
| Step 1 解析 | `agents/parser_agents.py`：5 个课题解析智能体（LLM） |
| Step 2 实体对齐 / Step 3 发现耦合 | `agents/coupling_agent.py`：检测智能体（LLM）按上述规则执行，配合 3 轮多采样合并 |
| Step 4 规范化 | `agents/coupling_agent.py::detect`：证据回填/投票/去重 |
| Step 5 评估 | `coupling_detector.py::evaluate` |
