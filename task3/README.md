## 运行方式（LLM 驱动）

本系统基于 DeepSeek 大模型 API 实现：文档解析与耦合检测均由 LLM 完成，不再使用硬编码规则。

```bash
# 方式一：使用代码内置默认 key（agents/llm.py）
python demo_cross_group.py

# 方式二：通过环境变量指定 key（推荐，避免 key 硬编码在代码中）
set DEEPSEEK_API_KEY=sk-xxxx    # Windows PowerShell
python demo_cross_group.py

# 方式三：质量门禁模式（演示推荐）——最多运行 N 次，直到精确率/召回率均达 100%
python demo_cross_group.py --retry 3
```

可选参数：`--data --logs --figures --retry N`。输出：运行日志（含每次 LLM 调用的耗时与 token 数）、
跨课题协同分析报告（Markdown）、3 张可视化图。

> 最终架构（单轮直接出结果，不预先知道耦合数量、不做验收重试）：
> ① 5 个解析智能体（LLM）抽取事实（实体/带时间事件/技术要点）；
> ② **单轮检测智能体（1 次 LLM 调用）**：Prompt 无数量暗示，要求"逐类穷举（时序/资源、新颖性/时间线、
>    技术路线），包含组内文档关系"，并内置易错点判定要点（软协同双形态、弱表述误报、不同资源强行关联）；
> ③ **确定性时间线复核**：基于解析事件比较时间/资源（退役 vs 使用、共享 vs 采购、专利日 vs 首创声明），
>    只补全不删除、不依赖 GT、不泄露数量；
> ④ 确定性后处理：分组去重（含证据文档集合）、负耦合回填过滤、新颖性同组、资源分配实体一致性兜底。
> 实测：单轮直接 **精确率 100% / 召回率 100% / F1 100%**（全程约 50 秒）。
>
> 说明：整个演示会调用 DeepSeek API 6 次（5 次文档解析 + 1 次耦合检测），需要可用的 API Key 与网络连接。
> key 可在环境变量 `DEEPSEEK_API_KEY` 中配置；API 地址/模型可用 `DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL` 覆盖。

## 检测算法概要（LLM 驱动）

解析与检测均由 DeepSeek 大模型完成，通过精心设计的 Prompt 引导模型执行：

1. **文档解析（5 个智能体）**：Prompt 要求模型把每份文档解析为 JSON 结构化语义表示——
   实体（含别名）、带时间的事件、属性断言、技术要点，并给出原文句子作为证据；
2. **耦合检测（1 个智能体）**：把 5 份解析结果整体输入模型，Prompt 要求执行三类推理并输出 JSON：
   - 实体对齐：不同说法是否指向同一概念/资源；
   - 时序推理：资源退役/删除与使用、专利与论文、采购与共享承诺等事件的时间冲突或依赖；
   - 技术路线耦合：重复投入/知识产权（负）vs 复用/baseline（正）；
3. **评估**：用 data/ground_truth.json 预埋的耦合做匹配评测（类型+课题组对+实体包含关系），
   计算精确率 / 召回率 / F1。

严重程度评级由模型给出：高（资源失效/重大冲突）、中（知识产权/时间线）、低（baseline 建议）。

> 答辩呈现要点见 `PRESENTATION.md`。
## 已知局限与改进方向（耦合检测不准确的原因）

LLM 驱动的检测在多次运行中可能出现漏检/误报（单次运行召回率通常 85.7%–100%），主要原因：

1. **大模型输出不确定性**：自回归采样即使 temperature=0 仍有波动；检测输入上下文约 1.3 万 token，模型可能遗漏分散在长文中的线索；
2. **上游解析误差传播**：解析智能体抽取的实体/事件不完整或有噪声（如把文档日期误标为 apply 事件、实体名不统一），检测基于有损中间表示推理，误差累积；
3. **跨文档三段推理难**：部分耦合需要串联 3 份文档的分散证据（如"调度策略复用"：实验报告建议 + 论文训练调度 + 结题报告合作数据），单次推理易漏；
4. **判定边界模糊**：新颖性、重复投入等类别边界不清，模型可能把"算力支持"误判为新颖性冲突、把"计划探索结合"误判为重复投入；
5. **实体表述不一致**：同一实体在不同文档/输出中的表述不同（全称 vs 缩写，如"自适应优先级抢占调度器" vs "APS"），导致评估匹配判为漏检/误报（即使语义正确）；
6. **评估匹配是近似匹配**：以"类型 + 课题组对 + 实体包含关系"近似判定命中，本身存在误差。

改进方向：多次采样投票合并、按课题组对拆分检测缩短上下文、实体标准化后处理、
为每类耦合提供正例/反例 few-shot、以及"LLM 抽取候选 + 规则校验硬约束"的两阶段方案（可选）。
